# astrbot_plugin_bilicard

B站 / 抖音视频解析卡片插件 for [AstrBot](https://github.com/AstrBotDevs/AstrBot)。

自动识别**群聊**中的分享，抓取信息后渲染成卡片图片回复——无需 @机器人、无需唤醒词、无需任何指令前缀：

- **B站**：视频链接、BV号、av号、b23 短链、QQ 小程序分享卡片
- **抖音**：分享口令、`v.douyin.com` 短链、网页地址

同时支持**订阅 UP主新投稿自动推送**与**下载视频发送到群**。

> 自动解析**仅在群聊生效**（私聊不触发）；指令与订阅推送不受此限制。
> 出图依赖远程渲染服务，**渲染失败时会降级成文字，但链接一定发出去**，不会静默丢消息。

## ✨ 功能

- **自动解析**：群里有人发 B站视频（链接 / BV号 / av号 / b23 短链 / QQ 小程序卡片），自动回复信息卡片
- **抖音解析**：群里发抖音**分享口令**（`7.86 复制打开抖音…https://v.douyin.com/xxx/`）或链接，自动回一张卡片（封面 + 时长 + 点赞）与原视频链接；开启视频上传后同样会下载发送**无水印**原片
- **信息丰富**：封面、时长、UP主头像、实时在线观看人数、标题、发布日期、BV号、简介、7 项统计（播放/弹幕/点赞/投币/收藏/分享/评论）、热门评论
- **AI 视频总结**：提取字幕用 LLM 生成一段总结（链接解析卡片专属）
- **AI 函数调用**：注册了 LLM 工具，与 AI 对话时即可让 AI 操作插件。**所有人**可用：查看订阅列表、获取某 UP主最新投稿、拉取订阅 UP主最新稿件（只读/拉取）；**仅管理员**：订阅 / 取消订阅 / B站登录 / B站登出（工具内 `event.is_admin()` 自鉴权，非管理员调用会被拒）
- **订阅推送**：订阅 UP主，有新投稿时自动渲染卡片推送到对应群（订阅卡片带"投稿了新视频"气泡）
- **视频下载发送**（可选）：下载视频后发到会话——默认作为**视频消息**（群里可直接点开播放），也可切换为**文件上传**（QQ 群文件）。发完即删本地文件，不占服务器空间。有 ffmpeg 时走 DASH 高清流，没有则自动退回单文件流
- **两种模板**：
  - 链接解析卡片：无顶部气泡 + 有 AI 总结
  - 订阅推送卡片：有顶部气泡 + 无 AI 总结
- **防刷屏**：同一视频冷却时间内不重复解析
- **访问控制**：触发范围（群/私聊）、基于 UMO 的会话黑/白名单、订阅/登录类指令仅管理员可用（查看订阅列表所有人可用）

## 📦 安装

1. 将本插件目录放到 AstrBot 的 `data/plugins/` 下（或在插件市场安装）
2. 安装依赖：
   ```bash
   pip install -r requirements.txt
   ```
   （主要是 `qrcode[pil]`，用于扫码登录生成二维码；`aiohttp` 通常已自带）
3. 重启 / 重载 AstrBot

## 🔑 关于 B站登录

- **看视频卡片**（信息、统计、在线人数、热门评论）：**无需登录**，开箱即用
- **AI 总结**（需要字幕）和 **订阅推送**（UP主投稿接口有风控）：**需要登录 B站**

> **登录态会过期**：B站 SESSDATA 默认约半个月失效（也可能因异地登录/风控提前失效）。本插件支持**自动续期**——只要登录时拿到了 `refresh_token`，后台每天会用 B站官方刷新机制自动续期，**免反复手动登录**。续期彻底失败时会回最近登录会话提醒管理员重新登录。
> 注意：自动续期只能给「仍有效」的会话续命，已彻底过期的救不回——首次需先 `/B站登录` 或填好 `ac_time_value` 引导一个新鲜会话。

两种登录方式（任选其一）：

### 方式一：扫码登录（推荐，自动开启续期）

发送指令 `/B站登录`，用 B 站手机 APP 扫描二维码并确认，插件会自动获取并保存 Cookie **及 `refresh_token`**，自动续期随即生效。

### 方式二：手动填写 Cookie

可手动提供账号 Cookie 中的 `SESSDATA` 和 `bili_jct`；若想同时**开启自动续期**，再额外填 `ac_time_value`（refresh_token）。

> `ac_time_value` **不在 Cookie 里**，需从浏览器 **localStorage** 取：F12 → Application/应用 → Local Storage/本地存储 → `https://www.bilibili.com` → 键 `ac_time_value` 的值。不填也能正常用，只是登录到期后要手动再填一次。

**使用浏览器插件获取（适合新手）：**

1. 安装 [Cookie Editor](https://cookie-editor.com/) 浏览器插件。
2. 登录 B 站后，打开 Cookie Editor，找到 `SESSDATA` 和 `bili_jct` 的值，复制。
3. 进入 AstrBot 后台 → AstrBot 插件 → 找到 **BiliCard**，将复制的值分别填入配置项 `bilibili_cookie` 的对应输入框中。

**使用开发者工具获取（适合进阶）：**

1. 在电脑端浏览器登录 [bilibili.com](https://www.bilibili.com)，按 `F12` 打开开发者工具。
2. 切换到「网络 / Network」或「应用 / Application」标签，找到任意一个 B 站请求的 Cookie。
3. 在其中找到 `SESSDATA=xxxxxx` 和 `bili_jct=xxxxxx`，把 `=` 后面的值分别填入插件配置。

> 订阅 UP主**不需要**你的账号去"关注"对方。插件只是用你的登录态去查询该 UP主的**公开投稿列表**（过 B站风控用），不会读取你的关注列表，也不会在你账号留下任何痕迹。

## 💬 指令

> 自动解析无需任何指令。下表标「管理员」的指令默认仅管理员可用，其余所有人可用。

| 指令 | 权限 | 说明 |
| --- | :---: | --- |
| （无需指令） | 所有人 | 直接发 B站视频链接/BV号/小程序卡片即自动出卡片 |
| `/订阅UP UID` | 管理员 | 订阅一个 UP主（如 `/订阅UP 486906719`），有新投稿自动推送到当前会话 |
| `/取消订阅UP UID` | 管理员 | 取消订阅 |
| `/订阅UP列表` | 所有人 | 查看当前会话已订阅的 UP主（只读） |
| `/最新UP UID` | 所有人 | 获取某 UP主**最新一条投稿**并发卡片（图+链接）。别名 `UP最新`/`最新稿件` |
| `/订阅最新` | 所有人 | 拉取本会话**所有订阅 UP主的最新稿件**逐个发卡片（最多前 10 位）。别名 `最新订阅` |
| `/下载视频 [BV号/链接]` | 管理员 | 下载该视频并发送到当前会话（形式按 `video_send_mode`）。不带参数则下载本会话最近解析过的那个视频。别名 `视频下载`/`B站下载`/`下载B站视频` |
| `/B站登录` | 管理员 | 扫码登录 B站（订阅 / AI 总结需要） |
| `/B站登出` | 管理员 | 清除已保存的登录信息 |
| `/sid` | 所有人 | AstrBot 自带指令，获取当前会话标识（用于配置访问名单） |

> UP主 UID 获取：打开 UP主主页，地址栏 `space.bilibili.com/` 后面那串数字就是 UID。

### AI 对话调用（无需指令）

上述功能也都注册成了 **LLM 工具**——配好 LLM 后直接问 AI（如「看看这个UP最近发了啥」「我订阅的UP有更新吗」），AI 会自动调用对应工具并发送卡片。

> **想让 AI 更稳定地走插件工具？** 把下面这段加进你所用 LLM 人格 / 系统提示的末尾（保存后对**新对话**生效）。这是提高命中率的关键——LLM 选哪个工具是它自己决定的：
>
> ```
> 【B站工具使用】
> 当用户想操作 B站订阅或查看 UP主视频时，优先调用下列对应工具（工具会直接把结果/卡片发给用户，调用后不要自己再复述）：
>
> 1. 看某 UP主最新视频 / 他最近发了什么 → get_up_latest_video(uid="UP主UID")
> 2. 看我订阅的UP最近更新 / 订阅的最新稿件 → get_subscribed_latest_videos()
> 3. 我订阅了哪些UP / 订阅列表 → list_subscribed_up()
> 4. 订阅某UP / 关注他更新 → subscribe_up(uid="UID")
> 5. 取消订阅某UP → unsubscribe_up(uid="UID")
> 6. B站扫码登录 → bili_login()
> 7. B站登出 → bili_logout()
>
> 规则：
> - UP主 UID 是 space.bilibili.com/ 后面那串数字。
> - 仅当工具获取失败、或用户明确要求"联网搜索 / 用网络搜索查最新"时，才改用 web_search。
> - 订阅 / 取消订阅 / 登录 / 登出仅管理员可用，非管理员调用会被工具拒绝。
> ```
>
> 注：发 B站视频链接自动出卡片是消息监听触发的，不经过 AI、不需要这段提示词。

| --- | --- | --- |

| `comment_count` | 热门评论数量 | 3 |

| `cooldown_seconds` | 同视频冷却秒数（0 不限制） | 60 |
| `enable_subscribe_push` | 订阅推送总开关（关闭暂停推送，订阅数据保留） | true |
| `check_interval_minutes` | 订阅检查间隔（分钟） | 10 |
| `subscriptions` | 订阅数据（JSON，后台可视化查看/编辑，默认含示例） | 示例 |

### 视频下载配置（配置页最下方，两个平台各一张卡片）

**📺 B站 · 视频下载发送**

| 配置 | 说明 | 默认 |
| --- | --- | --- |
| `enabled` | 自动下载并发送视频 | false |
| `on_subscribe_push` | 订阅推送时也发视频 | false |
| `quality` | 画质上限（360P/480P/720P/1080P/4K） | 720P |
| `max_size_mb` | 体积上限（MB），超限放弃 | 100 |
| `timeout` | 下载 + 合并总超时（秒） | 300 |
| `send_mode` | video=视频消息 / file=文件上传 | video |

**🎵 抖音 · 视频下载发送**

| 配置 | 说明 | 默认 |
| --- | --- | --- |
| `enabled` | 自动下载并发送视频 | false |
| `quality` | 画质（1080P/720P/540P） | 720P |
| `max_size_mb` | 体积上限（MB） | 100 |
| `timeout` | 下载超时（秒） | 180 |
| `send_mode` | video=视频消息 / file=文件上传 | video |

> 两个平台**完全独立**，可以只给抖音开下载、B站只发卡片。
> 抖音没有 AI 总结——它不提供字幕，`enable_ai_summary` 等只对 B站生效。

**抖音画质的实现方式**与 B站不同：分享页只返回一个播放地址（`bit_rate` 多档数组是空的，完整多档要走 Web API + `a_bogus` 签名），所以画质是靠**改写播放地址里的 `ratio` 参数**实现的：

只提供 **1080P / 720P / 540P** 三档，默认 720P（抖音自己的默认档）。同一视频实测：

| ratio | 实际体积 |
| --- | --- |
| `1080p` | 92.2 MB |
| `720p` | 69.0 MB |
| `540p` | 60.0 MB |
| `480p` / `360p` | **92.2 MB** ← 抖音不认，反而更大 |

**没有 480P/360P 是实测结论**：抖音对这两个值不是退回默认，而是返回了更大的文件，留着只会适得其反。

若播放地址里没有 `ratio` 参数（少数 CDN 直链），此项不生效，日志会如实显示"默认"。

## 📱 抖音解析

抖音分享到 QQ 通常是一段**口令**，插件会从里面把短链摘出来：

```
7.86 gJb:/ 复制打开抖音，看看【某某的作品】... https://v.douyin.com/iRxxxxx/ 复制此链接...
```

口令、`v.douyin.com` 短链、`douyin.com/video/xxx` 网页地址、发现页 `modal_id=` 都能识别。**解析默认开启、无需任何配置**。抖音卡片是极简版——**封面 + 时长 + 点赞**，下面附原视频链接。

实现走公开分享页（`iesdouyin.com/share/video/{id}/`）解析页面内嵌的 `_ROUTER_DATA`，**不需要抖音 Cookie、不需要 a_bogus 签名、不需要 Node.js**。代价是抖音改版页面结构时可能失效（日志会写明「未找到 _ROUTER_DATA」）。

开启视频上传后，抖音视频会下载**无水印**原片发送（把播放地址里的 `playwm` 换成 `play`）。抖音只有一档画质，`video_quality` 对它无效，但 `video_max_size_mb` 仍然生效。图集（多图）作品目前只发卡片和链接，不下载。

## 🎬 视频下载发送

在配置页最下方对应平台的卡片里打开「自动下载并发送视频」后，插件会下载视频并发到会话，**送达后立刻删除本地文件**。B站与抖音各有独立的开关、体积上限、超时与发送形式。

| `video_send_mode` | 效果 |
| --- | --- |
| `video`（默认） | 作为**视频消息**发送，群里可直接点开播放 |
| `file` | 作为**文件**上传（QQ 群文件），可下载保存，体积限制通常更宽松 |

### 画质与 ffmpeg

插件启动时会探测 ffmpeg，自动选择取流路线：

| 环境 | 路线 | 画质 |
| --- | --- | --- |
| **有 ffmpeg** | DASH 音视频分离流 + `ffmpeg -c copy` 合并 | 最高 1080P / 4K |
| **无 ffmpeg** | `platform=html5` 的 durl 单文件流（B站直接返回带音轨的 MP4） | 通常止步 720P |

> **AstrBot 官方 Docker 镜像自带 ffmpeg**，一般无需额外安装。B站 DASH 是音视频分离的，不合并就是无声视频，所以没有 ffmpeg 时只能走单文件流。
> 1080P 及以上需要登录 B站；4K / 大会员画质还需账号有对应权限，拿不到会自动降档。
> 选流时**优先 H.264(AVC) 编码**——B站现在很多视频默认给 HEVC/AV1，QQ 客户端解不了会黑屏。

### 体积控制

- 下载**前**按「码率 × 时长」预估体积，超过 `video_max_size_mb` 就自动降一档画质，全都超限则放弃（长视频会直接跳过并说明原因）
- 下载**中**按实际字节兜底，防止 CDN 不给 `Content-Length` 时撑爆磁盘

> 视频下载在**卡片渲染之前**就已排队，两者互不依赖：远程 t2i 渲染服务超时/故障时，卡片可能发不出来，但视频照常送达。

### 磁盘清理（不会累积）

视频存在数据目录的 `downloads/` 下，四重清理：

1. 文件送达后**立即删除**（成功、失败、异常都删）
2. 下载中途失败/超时/被取消，清掉所有中间产物（`.part`、分离的音视频流）
3. 插件**启动时**清空整个目录——兜住上次容器被强杀（重启 / OOM）留下的孤儿文件
4. 订阅轮询每轮顺带清扫超过 1 小时的残留；插件卸载/重载时再清空一次

### ⚠️ 部署要求：协议端要能拿到文件

两种发送形式都是先把**本地绝对路径**交给协议端（NapCat / Lagrange 等）。如果协议端和 AstrBot **不在同一个容器 / Pod**，它读不到这个路径，发送会失败。两种解法任选：

1. **挂载共享目录**（推荐）：让协议端容器能读到 AstrBot 的 `data/plugins_data/astrbot_plugin_bilicard/downloads/`，路径保持一致
2. **配置 `callback_api_base`**：在 AstrBot 全局配置里填一个协议端能访问到的 AstrBot 地址（如 `http://astrbot:6185`）。这样本地路径失败后，插件会自动把文件注册成 HTTP 直链再发一次

> 走直链方式时，协议端是回头来拉文件的，所以删除会延后 2 分钟（后台延迟，不阻塞指令）。日志里会写明走了哪条路，形如 `送达方式：视频消息（本地路径）`。

### 使用建议

先用 `/下载视频` 手动试一次，确认协议端能正常收文件，再打开 `enable_video_upload` 自动开关。群里链接一多会连着传大文件，比较吃带宽。

### 后台查看 / 编辑订阅

`subscriptions` 配置项以 JSON 形式记录所有订阅，可在 AstrBot 后台直接查看"哪个会话订阅了哪些 UP主"，也可手动编辑（改完需重载插件生效）：

```json
{
  "aiocqhttp:GroupMessage:123456789": [
    {"mid": "486906719", "name": "索尼音乐中国", "last_bvid": ""}
  ]
}
```

会话标识末尾即群号。手动新增时 `last_bvid` 留空即可（首次轮询会记录基线，不会把旧视频当新投稿推送）。指令 `/订阅UP` 的改动也会自动写回这里。

## ⚠️ 注意事项

- 卡片图片通过 AstrBot 内置的 HTML 渲染服务生成，需要 AstrBot 能联网访问其 t2i 服务。该服务是**公共远程服务**，繁忙时可能超过 `render_timeout` 导致卡片发不出来（日志会写"渲染超时"）。对策：把 AstrBot 的 `t2i_endpoint` **留空**（留空才会在官方多个端点间自动回退）、调大 `render_timeout`，或自建 t2i 服务
- 卡片图片本身**不落在插件目录**：它由远程服务生成并返回 URL，发送时框架会在 `data/temp` 存一份临时副本，由 AstrBot 自己的清理器管理（每 10 分钟检查，超过全局配置 `temp_dir_max_size`（默认 1024MB）时按时间从旧到新删）。嫌堆积可把该值调小，插件不介入这个目录
- B站 Cookie（SESSDATA）有效期通常为几个月，过期后请重新 `/B站登录` 或更新配置
- 不是所有视频都有字幕，无字幕时 AI 总结区块会自动省略
- 请勿高频触发，以免触发 B站风控
